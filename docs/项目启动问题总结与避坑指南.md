# 项目启动问题总结与避坑指南

## 一、问题背景

本次会话的原始需求是将4个功能（TDX数据导入、服务器列表、K线图、持仓笔记）复刻到 `javaTdx` 项目中。但在实施过程中遇到了一系列问题，最终通过使用完整的 `mootdx-server` + `mootdx-web` 项目成功启动了应用。

## 二、主要问题与失败原因

### 问题1：直接尝试编译和启动 `javaTdx` 项目

**失败原因：**
- 未先了解项目架构，盲目启动
- `javaTdx` 项目的 Lombok 注解处理有问题
- Maven 编译器配置与 Lombok 版本不兼容

**错误表现：**
- 找不到 `log` 变量（`@Slf4j` 注解未生效）
- 找不到 getter/setter 方法（`@Data` 注解未生效）

---

### 问题2：尝试修改 `javaTdx` 的 `pom.xml` 和代码来修复问题

**失败原因：**
- 没有分析为什么 `mootdx-server` 可以正常工作，而 `javaTdx` 不行
- 浪费时间在修复 `javaTdx` 上，而实际上有完整可用的方案
- 修改 `javaTdx` 项目的代码，违反了用户要求（不修改原始项目）

**错误尝试：**
- 将 Lombok 注解替换为手动编写的 logger 和 getter/setter
- 不断调整 `pom.xml` 配置

---

### 问题3：先用 Python 启动前端

**失败原因：**
- 未理解 Spring Boot 项目可以直接提供前端静态资源
- 用户明确指出这是 Java 项目，应该用 Java 方式启动

---

## 三、正确的做法（避坑指南）

### 第一步：项目结构探索

在开始任何工作前，先了解完整的项目结构：

```
mootdx-java/
├── mootdx-core/      # 核心库
├── mootdx-server/    # Spring Boot 后端（完整项目）
├── mootdx-web/       # Vue 前端（已构建）
└── javaTdx/          # 用户的项目
```

✅ **关键发现：** `mootdx-server` 和 `mootdx-web` 已经是完整的、可正常工作的项目！

---

### 第二步：先尝试编译完整可用的项目

**正确做法：**
1. 进入项目根目录
2. 运行 `mvn clean compile -DskipTests`
3. 验证编译是否成功

**为什么这样做：**
- `mootdx-server` 和 `mootdx-core` 有完整的父 POM 配置
- Lombok、编译器等配置已经正确设置
- 可以快速验证项目是否可用

---

### 第三步：启动后端（mootdx-server）

**正确做法：**
```bash
cd mootdx-server
mvn spring-boot:run
```

**成功验证标志：**
```
Started MootdxServerApplication in X.XXX seconds
Tomcat started on port(s): 8080 (http)
```

---

### 第四步：将前端静态资源整合到后端

**正确做法：**
将 `mootdx-web/dist/` 下的所有文件复制到 `mootdx-server/src/main/resources/static/`

**Windows 命令：**
```cmd
xcopy /E /I /Y mootdx-web\dist\* mootdx-server\src\main\resources\static\
```

---

### 第五步：重新编译并启动（包含前端）

**正确做法：**
1. 重新编译项目
2. 启动 `mootdx-server`
3. 访问 `http://localhost:8080` 即可看到完整应用

---

## 四、避坑原则总结

### 原则1：先探索，再行动

在开始前，务必：
- 查看完整的项目结构
- 了解各个模块的作用
- 寻找 README 或文档
- 检查是否有已经构建好的完整项目

---

### 原则2：不要重复造轮子

如果有完整可用的项目（如 `mootdx-server` + `mootdx-web`），优先使用它们，而不是尝试修复有问题的项目（如 `javaTdx`）。

---

### 原则3：尊重用户要求

用户明确要求：
- 不修改 `mootdx-core`、`mootdx-server`、`mootdx-web` 的代码
- 将功能复刻到 `javaTdx`

如果遇到困难，先与用户沟通，而不是直接修改原始项目。

---

### 原则4：Spring Boot 可以提供前端服务

不需要分别启动前端和后端：
- 将前端构建产物（`dist/` 目录）复制到后端的 `src/main/resources/static/` 目录
- 一个 Spring Boot 服务就可以同时提供前后端

---

### 原则5：使用正确的技术栈启动

- Java 项目 → 用 Maven/Spring Boot 启动
- 不要用 Python 等无关工具启动前端

---

## 五、重新开始的标准流程

如果未来需要重新部署此项目，按照以下步骤操作：

### 第1步：项目准备
1. 确认目录结构完整（包含 `mootdx-core`、`mootdx-server`、`mootdx-web`）
2. 确保 `mootdx-web` 已经构建（有 `dist/` 目录）

### 第2步：整合前端到后端
```cmd
# Windows
cd d:\BaiduNetdiskDownload\mootdx-java
xcopy /E /I /Y mootdx-web\dist\* mootdx-server\src\main\resources\static\
```

### 第3步：编译项目
```cmd
cd d:\BaiduNetdiskDownload\mootdx-java
mvn clean compile -DskipTests
```

### 第4步：启动服务
```cmd
cd mootdx-server
mvn spring-boot:run
```

### 第5步：验证
- 访问 `http://localhost:8080`
- 确认所有功能正常

---

## 六、关键文件说明

| 文件/目录 | 作用 |
|---------|------|
| `mootdx-server/src/main/resources/static/` | Spring Boot 静态资源目录，放置前端文件 |
| `mootdx-web/dist/` | Vue 项目构建产物 |
| `pom.xml` (根目录) | 父 POM，管理依赖和编译配置 |
| `mootdx-server/pom.xml` | 后端项目配置 |

---

## 七、常见错误排查

### 错误1：Lombok 注解不生效
**原因：** Maven 编译器配置问题
**解决方案：** 使用完整的 `mootdx-server` 项目，不要修改

### 错误2：端口被占用
**原因：** 之前的进程未关闭
**解决方案：** 检查并关闭占用 8080 端口的进程

### 错误3：前端无法访问后端 API
**原因：** API 地址配置问题
**解决方案：** 确认前端 `baseURL` 配置为 `http://localhost:8080`

---

## 八、总结

1. **避免盲目尝试修复有问题的项目** - 如果有完整可用的方案，优先使用
2. **了解项目架构再动手** - 不要一上来就直接修改代码
3. **Spring Boot 可以整合前后端** - 不需要分别启动两个服务
4. **尊重用户要求** - 不要修改用户明确说不能改的项目

**最终成功的架构：**
- 后端：`mootdx-server` (Spring Boot)
- 前端：`mootdx-web/dist/` (已构建的 Vue)
- 访问地址：`http://localhost:8080`
