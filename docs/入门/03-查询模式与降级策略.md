## 一、什么是降级策略？

### 1.1 现实问题

```
场景：你要查询100只股票的数据

问题1：新浪API突然挂了怎么办？
问题2：网络不稳定，请求超时怎么办？
问题3：某些数据源返回数据不完整怎么办？

答案：使用降级策略(FALLBACK)
```

### 1.2 降级策略的核心思想

```
┌─────────────────────────────────────────────────────────────┐
│                    降级策略工作流程                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  用户请求 ──→ 尝试数据源A ──→ 成功? ──→ 返回数据            │
│                  ↓ 失败                                     │
│              尝试数据源B ──→ 成功? ──→ 返回数据             │
│                  ↓ 失败                                     │
│              尝试数据源C ──→ 成功? ──→ 返回数据             │
│                  ↓ 失败                                     │
│              所有数据源都失败 ──→ 返回空/错误               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 三、批量查询模式 (BATCH)

### 3.1 为什么要分批？

```
问题：一次查询1000只股票，API可能会：
- 超时
- 返回数据不完整
- 直接拒绝请求

解决：将1000只分成多批，每批200只
```

### 3.2 批量查询流程

```java
// FallbackStrategyService.java 第91-155行
private List<StockInfoDTO> getStockInfoBatch(
    List<String> stockCodes, 
    List<String> dataSources
) {
    List<StockInfoDTO> result = new ArrayList<>();
    
    // 按优先级尝试每个数据源
    for (String source : dataSources) {
        
        // 1. 获取该数据源的批量大小
        int batchSize = getBatchSizeForSource(source);
        
        // 2. 分批查询
        for (int i = 0; i < stockCodes.size(); i += batchSize) {
            List<String> batch = stockCodes.subList(i, 
                Math.min(i + batchSize, stockCodes.size()));
            
            // 3. 查询这一批
            List<StockInfoDTO> batchResult = fetchFromSource(source, batch);
            
            // 4. 成功则累加结果
            if (!batchResult.isEmpty()) {
                result.addAll(batchResult);
            }
            
            // 5. 批次间延迟（防止请求过快被封）
            Thread.sleep(dataFetchConfig.getDelayMs());
        }
        
        // 6. 如果全部成功，直接返回
        if (result.size() == stockCodes.size()) {
            return result;
        }
    }
    
    return result;
}
```

### 3.3 批量查询图解

```
股票列表: [A, B, C, D, E, F, G, H, I, J] (10只)
批量大小: 3

第1批: [A, B, C] ──→ 查询 ──→ 结果1
延迟50ms
第2批: [D, E, F] ──→ 查询 ──→ 结果2
延迟50ms
第3批: [G, H, I] ──→ 查询 ──→ 结果3
延迟50ms
第4批: [J]        ──→ 查询 ──→ 结果4

合并: 结果1 + 结果2 + 结果3 + 结果4 = 完整结果
```

## 四、单笔查询模式 (SINGLE)

### 4.1 什么时候用单笔？

```
适用场景：
- 股票数量少 (<=10只)
- 追求成功率（每笔都单独重试）
- 数据源不稳定
```

### 4.2 单笔查询流程

```java
// FallbackStrategyService.java 第180-269行
private List<StockInfoDTO> getStockInfoSingle(
    List<String> stockCodes, 
    List<String> dataSources
) {
    List<StockInfoDTO> result = new ArrayList<>();
    
    // 对每只股票
    for (String stockCode : stockCodes) {
        StockInfoDTO stockInfo = null;
        
        // 按优先级尝试每个数据源
        for (String source : dataSources) {
            try {
                stockInfo = fetchSingleFromSource(source, stockCode);
                if (stockInfo != null) {
                    break; // 成功，跳出循环
                }
            } catch (Exception e) {
                log.warn("数据源{}查询失败: {}", source, e.getMessage());
            }
        }
        
        // 如果所有数据源都失败，创建一个空对象
        if (stockInfo == null) {
            stockInfo = createEmptyStockInfo(stockCode);
        }
        
        result.add(stockInfo);
        
        // 单笔延迟
        Thread.sleep(dataFetchConfig.getSingleDelayMs());
    }
    
    return result;
}
```

### 4.3 单笔查询图解

```
股票A: 尝试新浪 ──→ 失败 ──→ 尝试腾讯 ──→ 成功 ──→ 记录结果
延迟100ms
股票B: 尝试新浪 ──→ 成功 ──→ 记录结果
延迟100ms
股票C: 尝试新浪 ──→ 失败 ──→ 尝试腾讯 ──→ 失败 ──→ 尝试mootdx ──→ 成功 ──→ 记录结果
```

## 五、AUTO模式

### 5.1 自动选择逻辑

```java
// StockDataService.java 第200-210行
if (stockCodes.size() <= 10) {
    // 股票数量 <= 10，使用单笔查询
    // 原因：数量少，单笔成功率更高
    return getStockInfoFromAggregatedSingle(stockCodes, strategy);
} else {
    // 股票数量 > 10，使用批量查询
    // 原因：数量多，批量效率更高
    return getStockInfoFromAggregatedBatch(stockCodes, strategy);
}
```

### 5.2 选择依据

| 股票数量 | 推荐模式 | 原因 |
|----------|----------|------|
| 1-10只 | SINGLE | 单笔重试，成功率高 |
| 11-500只 | BATCH | 批量效率高 |
| 500+只 | BATCH + 分批 | 避免超时 |

## 六、降级策略配置

### 6.1 配置文件

```java
// DataFetchConfig.java 第12-92行
@Component
@ConfigurationProperties(prefix = "data.fetch")
public class DataFetchConfig {
    
    private int sina = 200;        // 新浪批量大小
    private int eastmoney = 50;    // 东方财富批量大小
    private int tencent = 100;     // 腾讯批量大小
    
    private int delayMs = 50;      // 批次间延迟
    private int singleDelayMs = 100; // 单笔延迟
    
    private String mode = "BATCH"; // 查询模式: BATCH/SINGLE/AUTO
    private String priority = "SINA,EASTMONEY,TENCENT"; // 优先级
    
    private boolean enabled = true; // 是否启用降级
}
```

### 6.2 动态配置API

```bash
# 查看当前降级配置

# 修改查询模式

  -d '"AUTO"'

# 修改优先级

  -d '"SINA,TENCENT,MOOTDX,EASTMONEY"'

# 修改延迟
curl -X POST "http://localhost:8080/api/fallback/delay?batch=100&single=200"
```

## 八、常见问题

### Q1: BATCH和SINGLE哪个更快？
**A**: 
- 股票数量少(<10)：SINGLE可能更快（没有分批开销）
- 股票数量多(>50)：BATCH更快（减少HTTP请求次数）

### Q2: 延迟参数怎么设置？
**A**: 
- 免费API建议50-100ms，防止被封
- 付费API可以设置0ms

### Q3: 如何知道降级是否生效？
**A**: 查看日志或调用测试接口：
```bash
curl "http://localhost:8080/api/fallback/test?stockCode=688606"
```
