## 一、配置持久化

### 1.1 为什么要持久化配置？

```
问题：
- 重启服务后，动态修改的配置会丢失
- 多个实例需要共享配置

解决：
- 将配置保存到数据库
- 服务启动时从数据库加载
```

### 1.2 持久化实现

**文件位置**: `DataSourceModeConfigController.java`

```java
// 保存配置到数据库 (第95-101行)
private void saveConfigToDatabase(String key, String value, String description) {
    systemConfigService.setConfigValue(
        "datasource.mode." + key,  // 配置键
        value,                      // 配置值
        description,                // 描述
        false                       // 是否加密
    );
}

// 从数据库加载配置 (第67-145行)
@PostConstruct
public void init() {
    loadConfigFromDatabase();
}
```

### 1.3 持久化的配置项

| 配置键 | 说明 | 默认值 |
|--------|------|--------|
| `datasource.mode.globalMode` | 全局查询模式 | FREE |
| `datasource.mode.defaultSource` | 默认数据源 | FREE |
| `datasource.mode.fallback.priority` | 降级优先级 | SINA,EASTMONEY,TENCENT |
| `datasource.mode.aggregated.dataSources` | 融合数据源 | SINA,TENCENT,MOOTDX,EASTMONEY |
| `datasource.mode.sina.batchSize` | 新浪批量大小 | 200 |
| `datasource.mode.delayMs` | 批量延迟 | 50 |
| `datasource.mode.singleDelayMs` | 单笔延迟 | 100 |

## 二、性能优化

### 2.1 批量大小调优

```java
// 不同数据源的推荐批量大小
Map<String, Integer> recommendedBatchSize = new HashMap<>();
{
    recommendedBatchSize.put("SINA", 200);        // 新浪支持大批量
    recommendedBatchSize.put("EASTMONEY", 50);    // 东方财富建议小批量
    recommendedBatchSize.put("TENCENT", 100);     // 腾讯中等批量
    recommendedBatchSize.put("MOOTDX", 100);      // 本地接口可以大些

```

### 2.2 延迟参数调优

| 场景 | batchDelayMs | singleDelayMs | 说明 |
|------|--------------|---------------|------|
| 免费API | 50-100 | 100-200 | 防止被封 |
| 付费API | 0-10 | 0-10 | 可以更快 |
| 本地接口 | 0 | 0 | 无需延迟 |

### 2.3 超时设置

// - 实时性要求高的接口：3000ms

## 四、最佳实践

### 4.1 场景一：追求稳定性

```bash
# 配置建议：
# 1. 使用FALLBACK模式
curl -X POST "http://localhost:8080/api/datasource-mode/global/mode" \
  -d '"FALLBACK"'

# 2. 设置多个备选数据源
curl -X POST "http://localhost:8080/api/fallback/priority" \
  -d '"SINA,TENCENT,MOOTDX,EASTMONEY"'

# 3. 适当增加超时时间
curl -X POST "http://localhost:8080/api/datasource-mode/source/SINA/config" \
  -d '{"timeoutMs": 8000}'
```

### 4.2 场景二：追求数据完整性

```bash
# 配置建议：
# 1. 使用AGGREGATED模式
curl -X POST "http://localhost:8080/api/datasource-mode/global/mode" \
  -d '"AGGREGATED"'

# 2. 使用最全策略
curl -X POST "http://localhost:8080/api/datasource-mode/aggregated/strategy" \
  -d '"MOST_COMPLETE"'

# 3. 配置字段优先级（确保关键字段有值）
# 编辑 DataSourceModeConfig.java 中的 fieldPriority
```

### 4.3 场景三：追求响应速度

```bash
# 配置建议：
# 1. 使用AGGREGATED模式
curl -X POST "http://localhost:8080/api/datasource-mode/global/mode" \
  -d '"AGGREGATED"'

# 2. 使用最快策略
curl -X POST "http://localhost:8080/api/datasource-mode/aggregated/strategy" \
  -d '"FASTEST"'

# 3. 减少超时时间
curl -X POST "http://localhost:8080/api/datasource-mode/fast/config" \
  -d '{"timeoutMs": 3000}'
```

### 4.4 场景四：节省API调用

```bash
# 配置建议：
# 1. 使用FREE模式（只调用免费API）
curl -X POST "http://localhost:8080/api/datasource-mode/global/mode" \
  -d '"FREE"'

# 2. 使用批量查询
curl -X POST "http://localhost:8080/api/fallback/mode" \
  -d '"BATCH"'

# 3. 增加批量大小
curl -X POST "http://localhost:8080/api/fallback/batch-size?sina=300"
```

## 五、常见问题排查

### 5.1 问题：返回数据不完整

**排查步骤**：
1. 检查当前模式
   ```bash
   curl "http://localhost:8080/api/datasource-mode/overview"
   ```
2. 检查数据源健康状态
   ```bash
   curl "http://localhost:8080/api/datasource-monitor/health"
   ```
3. 切换到AGGREGATED模式测试
   ```bash
   curl -X POST "http://localhost:8080/api/datasource-mode/global/mode" -d '"AGGREGATED"'
   ```

### 5.2 问题：查询速度慢

**排查步骤**：
1. 检查查询模式
   ```bash
   curl "http://localhost:8080/api/fallback/config"
   ```
2. 对于少量股票，使用SINGLE模式
3. 对于大量股票，使用BATCH模式并调大batchSize
4. 减少delayMs（如果是付费API）

### 5.3 问题：API被封

**解决方案**：
1. 增加delayMs
   ```bash
   curl -X POST "http://localhost:8080/api/fallback/delay?batch=100&single=200"
   ```
2. 减小batchSize
3. 使用多个数据源轮询
